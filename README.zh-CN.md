# blackbox-indicator-reverse

[English](README.md) · **中文**

> **当你的数字和 App 的数字对不上——一套可复现的黑盒市场指标反推方法。**
>
> 旗舰案例：交易所 App 的「资金流向」面板（币安式）。
> Reverse-engineering · data reconciliation · market-data algorithms.

---

## 1. 这是什么

一套可重复使用的手艺，专门对付一种你查不到答案的局面：指标的数字你看得见，
产生它的规则却没有任何地方写着。

它交付方法、陷阱清单，和三个可运行的实验室 —— 而重点就在实验室：
**反推的活由你亲手干**。每个 lab 都是一个你能提问、但不能翻看的黑盒，
答案锁着，等你主动去要。

多数人第一轮就错在同一个地方：**漏掉系数 2。** 本仓库教你系统地找到它
——不靠运气。

它是写给「自己手里有逐笔数据、同时有一个黑盒数字要对账」的人的 ——
包括不自己写代码、而是驱动 AI 搭管道的人。

## 2. 问题与答案 —— 结论放在最前面

**先说答案**：当你能做的检查全部通过、数字依然不对，你缺的是一个
**隐藏约定** —— 对方管道里一条从未写进文档的规则。它不是噪声，
所以会在残差里留下指纹，而指纹的形状就指明了它是哪一类规则。
读这个指纹是一套流程，本仓库就是这套流程。

你在复现一个**只能看到数值、看不到算法**的指标：

```
App 显示:   大单净流入  -6,392.77
你算的:     大单净流入  -10,000.00
```

阈值是**公开文档写明的**；数据源对账通过；时间轴校准通过；
数字依然不对。这不是你的 bug，是对方埋在口径里的**隐藏约定**。

本仓库把这种局面变成一门可复用的手艺：六步法、四条铁律、
七个有名有姓的陷阱，加三个**你来亲手反推**的可运行实验室。

## 3. 怎么用

### 跑一遍自己确认 —— 60 秒 demo（lab1）

```bash
python labs/lab1-static-threshold/mystery.py 1h "2026-09-18 20:00"
```

```
==============================================================
 资金流向分析 · SIM/USDT            （模拟教学数据）
 窗口: 2026-09-18 20:00 ~ 2026-09-18 21:00  (1h)
--------------------------------------------------------------
 加总净流入              +32,912.65 USDT
 大单净流入              +64,541.08 USDT
                    [大单: 单笔 >= 4,000 USDT]
--------------------------------------------------------------
 成交笔数                       321
 最新价                       99.09
==============================================================
```

不需要密钥、不联网、不用安装。脚本读的是仓库里自带的数据
（`labs/data/trades.csv`），三个 lab 的命令形态一致：
`python mystery.py <15m|1h|4h> "YYYY-MM-DD HH:MM"`。

App 把一笔 +32,270.54 的鲸鱼买单记成了 **+64,541.08**。
阈值公开（≥ 4,000 USDT）。把 12 个 4 小时窗口逐一与你的基线对账，
比值**精确等于 2.0000**——11 个有 大单成交 的窗口，11 次。
恒定比值是指纹：加性误差永远给不出它。有东西在乘。
是什么、为什么，就是这个 lab。

### 路线 A —— 只想用它

先把三个 lab 做完，再按 `01` → `07` 的顺序读 `docs/`。如果你是要复现自己
手上那个真实指标，动任何东西之前先读 `01`、`02`、`03`，并把
`04-trap-table.md` 当索引摊在手边 —— 它是按「检查成本从低到高」排的。

### 路线 B —— 想改它

纯 Markdown 加 Python：没有构建步骤、没有依赖、没有配置。

如果你是 **AI Agent**，被要求在这个仓库里干活，先读 [`AGENTS.md`](AGENTS.md)
—— 那是你在这个仓库里的行为契约。

## 4. 三个实验室

| Lab | 黑盒口径的秘密 | 教会你的失效模式 |
|---|---|---|
| [lab1 · 静态阈值](labs/lab1-static-threshold/worksheet.md) | 隐藏乘性因子（×2） | 阈值公开，口径仍不公开（★） |
| [lab2 · 分档口径](labs/lab2-aggregation-tiers/worksheet.md) | 档位边界的半开区间约定 [a, b) | 范围公开，边界不公开（★★） |
| [lab3 · 动态阈值](labs/lab3-dynamic-threshold/worksheet.md) | 每 15 分钟按前推 2h P90 重算阈值 | 什么都不公开（★★★） |

三个 lab 共用同一份 48 小时合成数据（种子固定，可完整复现，见
`labs/data/`）。**变的是黑盒的口径，不变的是你的方法。**

每个 lab 包含：`mystery.py`（"App"，可运行 CLI）、`params.lock`
（混淆后的答案——解码 = 作弊）、`worksheet.md`（练习）、
`solution/solution.md`（含真实运行数字的完整解答）。

## 5. 方法论（docs/）

六步法：锚点样本 → 时间校准 → 数据源对账 → 无参数基线 →
参数扫描 → 独立样本交叉验证。

顺序本身就是要点：前三步是地基。数据源没对账、时间轴没校准之前，
后面每一步的结论都是在解噪声 —— 所以永远不要用后面的步骤去掩盖前面的欠账。

四条铁律：先对账数据源，再谈算法 · 一切自算值必须逐点对账 ·
口径未明先怀疑自己的假设 · 区间一律左闭右开。

它们不是并列的清单，而是递进的关卡：铁律 1 不过关，
铁律 2 的那张表就没有意义；铁律 2 不做，铁律 3、4 的聪明没有落点。

七个有名有姓的陷阱（症状 + 对策），外加一章动态口径专论——
最难的一类，包括什么时候该**承认未解**、为什么「承认未解」
本身就是交付物。

## 6. 真实案例（docs/07）

币安 App「资金流向」面板，某永续合约品种（品种名隐去）。
成果：加总档**精确复现**（1 天窗口误差 0.005%）——包括那个
存活了三个版本没人发现的系数 2；大单档阈值反推为 0.095 BTC
（长窗口误差 0.1–4.2%）。诚实保留的未解：30 分窗口（误差 13.2%）、
卖方向单侧失准（21–34%）。

## 8. 边界与不适用

本仓库**刻意不做**的事：

- **它不是库。** 它是方法加三个 lab。没有东西可以安装，也没有东西可以
  import 进你的管道。
- **它给不了机制，只给行为。** 对账能锁死黑盒**做了什么**（×2 这个行为），
  但**为什么**这么做 —— 两种等价实现里到底是哪一种 —— 无法从数字里恢复。
  报告必须如实写出这一点，而不是挑一个更好听的故事。
- **它不承诺解出来。** 旗舰真实案例至今仍有未解部分，这一点是写进文档的，
  不是被抹平的。仓库在 `docs/05` 里还写明了什么时候「未解」才是诚实答案：
  能拿到的最细粒度仍粗于黑盒自身的刷新周期时；拿不到算法所消费的全量数据时；
  残差里两个参数纠缠在一起时。
- **它离不开你自己的数据。** 整套方法就是「你的逐笔数据」和「对方的数字」
  之间的对账。拿不到数据 —— 真实案例就拿不到全市场逐笔 —— 有些问题就是
  无解，再多方法论也补不上。
- **demo 数据是合成的。** `labs/data/trades.csv` 是生成的，
  不是任何真实交易所的市场数据。它存在，是为了让每个人得到的 lab
  逐字节可复现。

仓库自己的验收标准，也值得拿来验收你自己：把你的报告交给一个没参与过的
人，看他能不能只凭报告复算出你的每一个数字。不能 → 报告还没写完。
