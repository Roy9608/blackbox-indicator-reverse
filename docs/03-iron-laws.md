# 03 · 四条铁律

每一条都来自真实事故。违反任一条，你会得到一个**看起来像结论的错误**。
每条附：事故来源 / 违反后果 / 在哪个 lab 会踩到。

## 铁律 1：先对账数据源，再谈算法

> **在质疑"算法不同"之前，必须先证明"数据源相同"。**

用你的原始数据与官方聚合数据（如 K 线成交量字段）**逐分钟比对**：

```
逐分钟差异恒为 0.0000 → 数据源相同 → 差异必然来自算法
逐分钟差异不为 0      → 先修数据抓取，算法分析毫无意义
```

- **违反后果**：在一个错的数据源上反推"口径"，推出的每个参数都是垃圾。
- **Lab 位置**：lab1 任务 1。加总档 12/12 精确对上，才有资格谈大单。

## 铁律 2：任何自算值必须与目标值逐点对账

> **"推理看着对"不算成立。**

拿多个时间点的自算值与目标值**列表比对**，看差异是否稳定、
是否有系统系数。

- **真实事故**：某公式漏掉系数 2，数值差整整一倍，
  连续 **3 个版本**未被发现。根因：从未并表对过账。
- **违反后果**：错误以"功能正常运行"的姿态存活数月。
- **Lab 位置**：lab1 全程——那张 11/12 行比值 2.0000 的表，
  就是这条铁律的实体。

## 铁律 3：口径未明前，不要下"数据有问题"的结论

> **出现"零触发""零结果"时，先怀疑自己的假设。**

- **真实事故**：拿「单笔 ≥ X」去套某指标，零触发，于是推断
  "对方口径有问题"。真相：对方用的是**聚合档位**，
  不是单笔分档——错在拿固定阈值套动态口径。
- **违反后果**：把"我的模型错了"误诊为"他的数据错了"，
  从此与真相擦肩，还结下对数据方的无谓敌意。
- **Lab 位置**：lab2（随手写的 `<=` 边界）、lab3（静态阈值零精确匹配时）。
- **自检口诀**：结论里出现"对方有问题"，先数一数自己列过几种自己的假设。

## 铁律 4：区间切片必须左闭右开

```python
# ❌ 错：hi 端用 bisect_right 会多算一格，整列平移
i = bisect.bisect_right(buckets, lo)
j = bisect.bisect_right(buckets, hi)

# ✅ 对：时间切片两端都用 bisect_left
i = bisect.bisect_left(ts_list, lo)
j = bisect.bisect_left(ts_list, hi)
```

- **症状**：K 线第 N 桶数值 == 原始数据第 N−1 桶数值（整体错位一格）。
- **数值分档**是同一纪律的另一面：`bisect_right(EDGES, q)` 给出 [a, b)。
  两处**不要混用**。
- **Lab 位置**：lab2 全程 + lab3 的窗口切片。

## 四条律的内在结构

```
铁律 1（数据源）── 地基：数据一致才谈算法
铁律 2（逐点对账）── 手段：一切结论的唯一来源
铁律 3（怀疑自己）── 心法：先证己罪，再指人非
铁律 4（左闭右开）── 纪律：边界处理不留惯性思维的缝
```

它们不是并列的清单，而是**递进的关卡**：
1 不过关，2 的表没有意义；2 不做，3/4 的聪明没有落点。
