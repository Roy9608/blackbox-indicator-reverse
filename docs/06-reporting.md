# 06 · 输出规范：反推报告怎么写

反推的产出不是"我搞定了"，是一份**能让别人复核、能让三个月后的
自己复核**的报告。本仓库（黑盒指标反推）与另两册
（回测诚实性、实盘系统可靠性）共享同一条价值观：
**可复核性优先于结论本身。**

## 报告五要素（缺一不可）

### 1. 已验证的公式（含系数）

写清口径、单位、边界约定、方向符号：

```
大单净流入 = 2 × Σ(±quote | quote ≥ 4000)
  ± = 买单 +1 / 卖单 −1
  时间窗口: [t0, t1) 左闭右开
  单位: USDT（quote 额，非币量）
```

### 2. 误差表（逐窗口/逐样本）

自算值 vs 目标值 vs 误差，**全部列出，包括对上的**。
示范见 `labs/lab1-static-threshold/solution/solution.md` 的
12 行对账表——包括那行"0 笔大单，0/0 无意义"的诚实标注。

### 3. 未解问题（诚实标注，不要粉饰）

真实案例原文照录的格式：

> - 30分窗口误差 13.2%（阈值动态性未完全建模）
> - 卖方向误差（21–34%）大于买方向（1–3%），原因未明

未解不是失败，**藏起来的未解才是事故**。
读者依据"哪些可信、哪些不可信"做决策，这份清单就是信任的边界。

### 4. 对下游的影响

明确告诉使用方：

- 哪些字段可信（加总档：误差 0.005%，可放心用）
- 哪些字段需谨慎（大单档长窗口：误差 0.1~4.2%，方向性参考可用，
  精确值不可用）
- 哪些不可用（30 分窗口：误差 13.2%，禁止用于信号）

### 5. 失误记录

这次踩了哪些坑，供下次避免。示范：
`labs/lab3-dynamic-threshold/solution/solution.md` 的"失误记录"节
（"静态 T=500 差 1.4% 时差点收工"）。

失误记录的价值随时间递增——它是团队/个人的"陷阱快查表"原料
（`04-trap-table.md` 就是这么长出来的）。

## 好报告 vs 坏报告

| | 坏报告 | 好报告 |
|---|---|---|
| 结论 | "已复现资金流向指标" | "加总档 12/12 逐点为 0；大单档存在 ×2 因子，11/11 窗口比值 2.0000；30 分窗口未解（13.2%）" |
| 证据 | "误差很小" | 逐窗口误差表，含独立样本 |
| 置信 | "应该是每笔两侧各计" | "行为锁定为 ×2；两种候选机制无法用现有数据区分，待源码确认" |
| 边界 | 不提 | 明确列出未解项与下游使用建议 |

**一句话检验**：把你的报告交给一个没参与过的人，
他能不能只凭报告复算出你的每一个数字？
能 → 合格；不能 → 回去补表。

## 与"confirm-before-write"文化的关系

反推报告是对内的。对外发布（如开源、如给数据方提工单）前，
过一遍脱敏：内部路径、账户、持仓品种、协作人信息——
**证据留在报告里，身份留在报告外。**
